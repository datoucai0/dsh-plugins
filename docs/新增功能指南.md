# 新增功能指南（以后新需求照这个做）

> 目标：在**不影响生产**的前提下，把新功能做出来、验证通过、再切生产。

## 一、要新增一个功能（合并进 dsh-local-kit）

1. **新建源包**：`packages/<feature-name>/`，形状照抄现有 4 个（最简可参考 `packages/dsh-drag-and-drop/`）：
   ```
   packages/<feature-name>/
   ├── package.json          # name / version / description(中文) / main / exports{".","./client","./package.json"}
   │                         # dsh.bundle.patch=./cordis.patch.yml ; dsh.client={platform:"web", inject:[...包名]}
   ├── cordis.patch.yml      # - insert: [ - id: <row-id>, name: '<feature-name>' ]
   ├── lib/index.js          # host 半边：export const name / export const inject / export function apply(ctx)
   ├── lib/client.js         # client 半边：window.__ModuleLoader__.load({id:"<feature-name>", factory:(require)=>{...; return module.exports;}})
   └── README.md
   ```
2. **登记到构建脚本**：在 `scripts/build.mjs` 的 `features` 数组里加一行：
   ```js
   { key: "<feature-name>", dir: `${SRC}/<feature-name>` },
   ```
3. **构建**：`node scripts/build.mjs` → 会把它并进 `packages/dsh-local-kit/`
4. **校验**：`node scripts/verify.mjs`
5. **隔离验证**（强烈建议）：在试验 profile 里试跑，不动生产
   ```powershell
   # 试验 profile 已存在：C:\Users\Administrator\.dsh\profiles\local-kit-test（端口 3081）
   dsh plugin --profile local-kit-test remove dsh-local-kit
   dsh plugin --profile local-kit-test add "file:C:/Users/Administrator/dsh-plugins/packages/dsh-local-kit"
   dsh local-kit-test
   # 浏览器打开日志里打印的 http://127.0.0.1:3081/?token=... 逐个确认功能
   ```
6. **切生产**（按 `~/.dsh/changes/RULES.md`）：
   - 先存档（写清改动/回滚/验证方式）+ 备回滚物
   - `dsh plugin --profile web remove dsh-local-kit` + `add file:.../packages/dsh-local-kit`
   - **四层核验**：`dependencies` / `dsh.profile.bundles` / `node_modules/dsh-local-kit` / `pnpm-lock.yaml`
   - 重启（`C:\Users\Administrator\.dsh\restart-dsh-web-safe.ps1`，脱树方式）
   - 重启后核对引导页 client 行 + 目视确认

## 二、要新增一个**独立**插件（不并进 kit）

1. 建 `packages/<name>/`（同上形状）
2. 直接装：`dsh plugin --profile web add "file:C:/Users/Administrator/dsh-plugins/packages/<name>"`
3. 四层核验 → 重启 → 确认

## 三、常见坑

| 坑 | 说明 |
|---|---|
| 功能装了但不出现 | 九成是 client 注册 id ≠ 包名（见 `合并技术契约.md` 第一条） |
| UI 座位重复 | 合并包与源包**同时**安装/在 bundles 里（同一功能注册两次） |
| 只改了清单就以为生效 | 必须四层核验；`node_modules` 是实体副本，改源目录**不会**自动同步，需 remove+add |
| 中文 JSON 校验被误判损坏 | 用 `node scripts/verify.mjs`（严格 UTF-8），不要用 PowerShell 的 `ConvertFrom-Json` |
| 构建脚本报找不到源目录 | `scripts/build.mjs` 的 `SRC` 必须指向 `dsh-plugins/packages` |
| 重建后 README 消失 | 构建会清空输出目录；README 来自 `templates/` 模板（脚本自动拷入），模板别删 |
