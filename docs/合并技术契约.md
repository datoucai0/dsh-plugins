# 合并技术契约（改动合并包前必读）

本文件记录**把多个插件合并成一个 DSH bundle 时必须遵守的硬约束**。违反其中任何一条，症状都是"装上了但功能不出现"或"重复注册座位"，且不报错。

## 一、客户端注册 id 必须等于包名 / 图行 id

官方类型定义原文（`@deepseek-ai/dsh-client-modules` 的 `manifest.d.ts`）：

> `ClientBundleRegistration.id` —— *"Plugin id (package name) — the registration key; must match the graph row being executed."*

因此：

- **不能**把 N 个 `client.js` 直接拼接（那会注册成 N 个非图行 id → 永不激活）；
- 必须做成**一个**以合并包名（`dsh-local-kit`）为 id 的注册：
  ```js
  window.__ModuleLoader__.load({
    id: "dsh-local-kit",
    factory: (require) => { /* 各功能体在各自 IIFE 内运行，最后合并成一个插件 */ }
  });
  ```

## 二、client 的 `inject` 是 cordis 服务名，不是包名

- `exports.inject = ["slots"]` 这类**服务名**由 client 插件声明（如 `slots` / `locale` / `sessions`）；
- **包名**列表属于 `package.json` 的 `dsh.client.inject`（boot graph 的依赖边）。

合并时：`package.json` 用各功能包名的**并集**；JS 里用各功能服务名的**并集**（构建脚本在工厂运行时求并集，避免手工维护）。

## 三、一个包 = 一行 patch = 一个 client 工厂

- `dsh.bundle.patch` 指向一个 `cordis.patch.yml`，里面 `- insert:` 一行；
- 该行的 `name` 就是包名，客户端工厂 id 也必须是包名。

## 四、功能体抽取锚点

`scripts/build.mjs` 从每个源插件的 `lib/client.js` 抽取"工厂体"，锚点是该文件末尾的
`return module.exports;`（其后紧跟工厂的收尾 `}`）。
**新功能的 `client.js` 必须保持这个形状**，否则抽取会失败或截断。

## 五、dsh 版本相关的兼容补丁（已知）

dsh 0.1.7 把 `conversation.chat.turnTail` 声明为 **LIST slot**：每个贡献都需要稳定的 `id`
（旧契约是 `select` 链式）。`dsh-file-mentions` 仍 ship 旧形状：单独安装时只是渲染期软失败，
**合并后宿主行激活较晚，会真正出问题** → 构建脚本里带了对应的功能体兼容补丁。

> 该补丁由外部（OpenClaw）加入，属于本工程的关键资产：**新增/修改功能时不要删除它**。

## 六、依赖保留（4 源包卸载后仍要能跑）

host 半边会 import 一些 bare specifier（当前是 `@deepseek-ai/schemastery`、`zod`）。
4 个源插件卸载后这些依赖不会自动保留 → `scripts/build.mjs` 会扫描 host 半边的 bare import，
解析出版本并写入合并包的 `dependencies`。新增功能若引入新的 bare import，重建即可自动带上。
